## Guión 3 — Cómo un título de pull request roba tu API key · TUTORIAL

**Pilar:** Tutorial · **Fórmula:** Question · **Driver:** Utilidad · **Duración:** 24s

### Hook (0-3s)

> "¿Puede el título de un pull request robarle la API key a una IA? La respuesta corta es sí. Y ya pasó esta semana."

### Payoff (3-15s)

- **3-5s:** "Un investigador escribió una instrucción oculta en el título de un PR. Tres agentes distintos cayeron en la trampa el mismo día."
- **5-8s:** "Claude Code Security Review, el Gemini CLI Action y el Copilot Agent. Todos publicaron su API key en un comentario."
- **8-12s:** "Se llama indirect prompt injection: la IA lee el título como si fuera una orden tuya y la ejecuta."
- **12-15s:** "Defensa práctica: nunca le des secretos al agente que pueda escribir comentarios públicos. Y revisá títulos antes de procesarlos."

### CTA (15-25s)

> "Si tenés un agente conectado a tu repo, hoy vale la pena auditar qué permisos tiene. Guardalo y mandáselo al que mantiene tus pipelines."

### Visual notes

- Editor con un pull request abierto. Resaltar el título en rojo: el texto inocente arriba, y debajo en monoespaciada los caracteres ocultos que activan la inyección. Pantalla partida: a la izquierda el flujo del agente, a la derecha el comentario que termina filtrando "API_KEY=...". Cierre con tres bullets blancos: "1. Permisos mínimos. 2. Revisar inputs. 3. Secretos fuera del runtime."

### Caption Instagram

Esta semana un solo prompt injection rompió tres herramientas a la vez: Claude Code Security Review, Gemini CLI Action y Copilot Agent. El ataque vivía en el título de un pull request, y los tres agentes terminaron filtrando su propia API key. Indirect prompt injection ya no es teoría: es la vulnerabilidad más explotada en agentes en 2026. Tres defensas concretas adentro.
